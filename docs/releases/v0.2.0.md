# Pi Companion 0.2.0

Pi Companion is a standalone, read-only Windows companion for Pi agents, built with Tauri 2, Rust, and a local React/8bitcn pixel interface.

## What's new

- A compact 360×300 Office window, with a 280×240 minimum and independent 1×/2× artwork sizing.
- Optional Taskbar mode: a transparent, borderless strip 104 logical pixels high above the selected monitor's taskbar. Desks keep native-size 64×64 artwork and scroll horizontally for larger rosters. The strip does not embed into Explorer.
- Always-visible retro status bubbles above each agent, with downward pixel tails. Names remain available on hover, keyboard focus, accessible labels, and Office details.
- Shorter attention poses across all six characters, keeping the original palette and the other animation states unchanged.
- Workspace filtering by the exact path shared by Pi, live connected idle agents, and automatic removal of stale or disconnected agents.
- Office size, position, and pin restoration; guarded tray/shortcut recovery; and same-monitor fullscreen hiding that preserves an explicit user hide.

## Downloads and installation

- `Pi-Companion-0.2.0-Windows-x64-setup.exe`: Windows x64 NSIS installer.
- `Pi-Companion-0.2.0-Observer.zip`: optional observer source and third-party notices for inspection or development. The observer is already bundled with the installer.
- `SHA256SUMS.txt`: SHA-256 hashes for the installer and observer archive. Compare them with `Get-FileHash -Algorithm SHA256 <downloaded-file>` in PowerShell.

The installer is **unsigned**. Windows can display an unknown-publisher or reputation warning; a formal GitHub Release does not remove that warning. Check the repository, release tag, and file hash before deciding whether to install. No signing certificate or signing service is configured.

Microsoft WebView2 is required. If it is missing, the installer downloads Microsoft's bootstrapper/runtime, so first installation can require internet. The app does not bundle Electron, Node.js, a Pi runtime, or a separate Node bridge process.

## Connect Pi once

1. Start Pi Companion and open **Menu → Connect Pi**. The app prepares its bundled observer in a stable private per-user folder and shows the actual path and a settings example.
2. Add that observer path to the existing `extensions` array in your Pi settings, normally `~/.pi/agent/settings.json`. Preserve other settings. If replacing Pi Office, remove its old observer entry rather than loading both.
3. Start Pi normally, or run `/reload` once in each already-open session when its response, compaction, and subagent work are idle. Future ordinary launches load the observer automatically.

No special launch command or environment variable is needed. The app does not edit Pi settings for you. The observer automatically discovers the app-managed connection file beside its exported directory. After upgrading, an idle `/reload` or a normal Pi restart loads the refreshed observer code. Closing the companion does not stop Pi.

Observation is metadata-only and local: session/agent names, lifecycle and state, tool names, model, and workspace path. Prompts, message contents, tool arguments, and tool results are not sent. The authenticated bridge listens only on `127.0.0.1:4318`; it cannot control agents.

## Verification and known limits

The approved layout and sprite illustrations were reviewed offline. Local validation passed 264 tests: 122 frontend, 51 observer, 8 pixel-authoring, and 83 Rust core/shell tests, plus TypeScript, formatting, strict core/shell Clippy, and public-source checks.

Publication is gated on a fresh Windows build of the exact release commit: frontend/observer checks, production bundle verification, pixel-authoring tests, Rust workspace tests, formatting, strict workspace Clippy, and NSIS packaging. The release workflow verifies the uploaded installer, observer archive, and checksum file by downloading them again before publishing.

**Native Windows GUI acceptance remains outstanding.** Automated tests and offline illustrations do not establish WebView2 text/layout, native transparency, hit testing, z-order, taskbar auto-hide, mixed DPI, monitor removal, fullscreen behavior, tray/hotkey recovery, accessibility, sleep/resume, or installation/uninstallation behavior on a real desktop. The native Windows integration was not compiled or run in the local Linux validation environment; the exact-commit Windows workflow provides separate build/test evidence. No browser or native GUI pass is claimed.

See the repository's validation and taskbar acceptance checklist for the remaining desktop checks. Third-party notices are included in both the installer and observer archive; a project-wide source/artwork license has not been selected.
