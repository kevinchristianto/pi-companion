# Pi Companion 0.2.2

This update adds distinct character assignment, a saved idle/ready visibility option, and a randomized, display-only Demo mode. Existing sprite artwork, native window behavior and automatic Pi observer connection are preserved.

## What's changed

- Illustrated agents use all six character designs before repeating one. Larger rosters distribute repeats evenly. Existing assignments stay stable where possible through status updates, reorders and Office/Taskbar switches. Workspace and idle filtering can reassign duplicates to unused designs; hidden and text-only agents do not reserve visible characters.
- **Menu → Show idle / ready agents** hides or restores Ready agents in both layouts. It defaults to on and saves the choice locally. Hidden agents remain connected and reappear when their status changes. Working, thinking, needs-input, error, completed and unknown states stay visible. An idle-only view explains why it is empty instead of implying a lost connection.
- **Menu → Demo mode** starts a clearly labeled fictional office. It begins with six simulated agents, then varies membership between two and six and randomizes activities every four seconds. It does not start, stop, message or assign tasks to Pi agents.
- Demo and live rosters remain separate. Turning Demo mode off restores the latest live snapshot and prior live workspace selection. Demo activation is not saved across restarts. Pause motion, reduced motion and hidden/fullscreen-hidden windows also pause random demo changes.

## Download and upgrade

- `Pi-Companion-0.2.2-Windows-x64-setup.exe`: Windows x64 NSIS installer.
- `Pi-Companion-0.2.2-Observer.zip`: optional observer source and third-party notices. The installer already includes the observer.
- `SHA256SUMS.txt`: verify downloads with PowerShell's `Get-FileHash -Algorithm SHA256`.

The installer is **unsigned**. Windows may display an unknown-publisher or reputation warning. A formal release does not remove that warning. Microsoft WebView2 is required; if missing, installation downloads its bootstrapper/runtime and needs internet.

Existing Pi observer configuration continues to work. No observer or protocol change is required for these features. New users start Companion, open **Menu → Connect Pi**, and add the displayed observer path once to Pi's `extensions` setting. The app does not modify Pi settings. The bridge remains authenticated, read-only and local to `127.0.0.1:4318`; prompts, message contents and tool arguments/results are not sent.

## Verification and known limits

Local validation passed 241 tests: 182 frontend, 51 observer and eight pixel-authoring tests. Frontend/observer TypeScript checks, production build and provenance checks, the public-source audit, whitespace checks and independent source review passed. All 15 sprite PNGs remain unchanged.

Publication requires the exact release commit to pass the Windows workflow: the full frontend/observer suite, production build, pixel tests, Rust formatting, Rust workspace tests, strict workspace Clippy and NSIS packaging. The workflow downloads and SHA-256 verifies all three uploaded release assets before publication.

**Native Windows GUI acceptance remains outstanding.** Local browser automation could not launch because of executor socket restrictions, and the local executor had no Cargo toolchain. No local browser or native GUI pass is claimed. Windows CI supplies separate compile/test evidence, not proof of WebView text/layout, physical mixed-DPI placement, transparency, taskbar auto-hide/fullscreen handling, installation behavior, accessibility or tray/hotkey recovery. Keep **Ctrl+Shift+P** and tray access available while trying Taskbar mode.

See [revision validation](../VALIDATION-ROSTER-DEMO.md) and the existing taskbar release checklist for remaining checks. Third-party notices are included; a project-wide source/artwork license has not been selected.
